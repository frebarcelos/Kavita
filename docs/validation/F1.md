Data: 2026-10-17. Estado: **v1.0 funcional confirmada pelo usuário no tablet para download e leitura offline; aceite completo da F1 em andamento**.

## Incremento implementado

- [Compose](../../deployment/offline/compose.yaml) com biblioteca bind somente leitura, pasta obrigatória sem criação implícita, dados operacionais em volume Docker e acesso inicial limitado a 127.0.0.1.
- [Preparação](../../scripts/offline/prepare.mjs) de EPUB sintético com três capítulos, sentinelas descartáveis, .env local e manifesto SHA-256. Recusa sobrescrever pasta existente.
- [Manifesto](../../scripts/offline/library-manifest.mjs) para detectar arquivos adicionados, removidos, renomeados ou alterados, inclusive alterações de mesmo tamanho. Recusa links e gravação do manifesto dentro do acervo.
- [Verificação do container](../../scripts/offline/verify-readonly.mjs) que exige montagens efetivas protegidas e usa apenas sentinelas sintéticas para testar criação, alteração, exclusão e renomeação. Compara hashes antes/depois.
- [CI](../../.github/workflows/offline-server.yml) preparada para repetir os testes, iniciar container descartável, aguardar saúde e verificar a montagem. **Não executada remotamente nesta tarefa.**
- [Guia operacional](../../deployment/offline/README.md) para inicialização, contas, acesso LAN e ciclo de leitura no S6 Lite.

A imagem fixada é upstream 0.9.1 por digest. Não é um build do checkout local; compatibilidade com o Kover do fork ainda não foi comprovada. Não houve mudança no código dos aplicativos, esquema de banco ou acervo pessoal.

## Conta de leitura criada; acesso LAN aguarda firewall

O usuário confirmou por captura de tela a conta comum de leitura, com Login e Download e sem Admin. A publicação Docker continua em 127.0.0.1:5000. Foi identificada a interface Wi-Fi doméstica e preparada uma regra de permissão limitada à sub-rede, acompanhada de bloqueio das demais origens IPv4 nessa porta/interface. A criação foi negada pelo Windows (erro 5, privilégio administrativo ausente); nenhuma regra foi criada e o bind Docker não foi alterado.

Foi preparado um script administrativo local em _temp/offline-f1/enable-lan-firewall.ps1, fora do versionamento, com IP/interface específicos e validação de IP atual. O usuário deve executá-lo em PowerShell do Windows como administrador; depois conferir as regras antes de publicar somente no IP privado. A confirmação por outro dispositivo e o ciclo offline permanecem pendentes.

## Acesso LAN habilitado e verificado

Após o usuário executar o helper administrativo, foram conferidas as duas regras efetivas do Windows: entrada TCP na porta 5000, somente no endereço privado e na interface Wi-Fi; permissão para a sub-rede doméstica e bloqueio das demais origens IPv4, com EdgeTraversalPolicy Block. O perfil de rede do Windows não foi alterado.

O .env local foi atualizado para publicar somente no IP privado atual do Wi-Fi. O Compose recriou o container preservando o volume de configuração. A inspeção confirmou exatamente esse endereço, sem publicação em 0.0.0.0 ou IPv6. O container ficou saudável; GET / e GET /api/health responderam HTTP 200 pelo endereço privado a partir do PC.

A verificação ativa foi repetida após a recriação: criação, alteração, exclusão e renomeação das sentinelas negadas; o manifesto confirmou os cinco arquivos com hashes idênticos. Nenhum encaminhamento no roteador ou túnel externo foi configurado por esta tarefa.

A partir desta configuração, usar http://IP-PRIVADO:5000 também no PC, em vez de localhost. IP, interface e regras concretas permanecem apenas na configuração local. Se o endereço do Wi-Fi mudar, revisar regras e bind antes de reaplicar; não ampliar a publicação para contornar a mudança.

**Pendente:** abrir o endereço no navegador do S6 Lite na mesma rede, confirmar acesso como leitor e executar o ciclo Kover completo. A resposta HTTP observada no PC não comprova conectividade de outro aparelho. A F1 continua em andamento.
